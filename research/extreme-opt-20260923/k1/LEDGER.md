# K1 optimization campaign — 2026-09-23

All candidates are isolated copies of `../baseline`. Main workspace source has not been edited by this worker. SDK 0.8.1, exact baseline Cargo.lock, `CARGO_INCREMENTAL=0`. Static baseline: 42,539 cycles / 154 instructions. Static schedules are screening evidence, not hardware performance measurements. Root coordinates full-build correctness and Arena comparison.

## Invariants

- `normalize_native_input(device, x, input_rms_weight)` remains in every candidate. It computes input RMS including EPS, loads every input RMS weight, multiplies it into normalized input, rounds to BF16, and dynamically calibrates both FP8 activation components.
- Q/K/V weights and channel scales all contribute to their projections. Q/K RMS weights remain applied. Per-head value normalization remains present.
- Both supplied RoPE tables and `rope_offset` are used. K/V scatter uses `kv_offset`; Q writes the original output. Device entrypoint signatures and host harness remain unchanged.
- No case-dependent shortcut, assumed constant input, discarded scale, or historical A010 `_weight` implementation is used.

## First screening batch

These six compile invocations were serialized within their own shell but overlapped other workers' SDK activity in a shared target. Root will recompile any selected winner under the shared whole-invocation flock before acceptance. Cargo.lock bytes remained identical to baseline for every probe.

- **p01-rms-vrf:** Write the final head RMS scalar straight to VRF. All three head normalizations retain arithmetic, EPS, sqrt, division, BF16 boundaries, and mappings. PASS **42,124 / 151**, -415 cycles (-0.976%). Three Sub preloads disappear. Tail sqrt output now ends at 40,250 and final V normalization ends at 40,595; V scatter/sync ends at 42,124. DMA scheduling also shifts, so the net 415-cycle reduction is not just three times the removed preload. **First candidate passed to root.**
- **p02-rope-vrf:** Write the sine product straight from Main to VRF. PASS **42,689 / 152**, +150 cycles despite two fewer instructions. Main-to-VRF reserves Sub; fewer commands do not guarantee better overlap. Do not combine blindly with p01.
- **p03-input-rms-vrf:** Write input RMS to VRF and relabel already initialized all-reduce copies to shard names. PASS **42,539 / 153**, same makespan with one fewer instruction. Neutral static screening; command-count change can still be measurable on hardware, but no such gain is claimed.
- **p04-rope-dm:** Replace gathered cos/sin row HBM round trips by direct DM relayout/replication. PASS **43,923 / 157**, +1,384 cycles (+3.25%). Added cross-cluster transfers and synchronization outweigh two removed HBM stores. Reject current form.
- **p05-input-trf:** Remove explicit dense DM copy and fetch directly from the switch's transposed output into canonical TRF. Compiler rejects `StoTrf`: fetch sequencer leaves a live input axis unread, `(H / 8 % 15, H / 120 % 4)`. Reject; the old explicit layout restoration cannot simply be deleted.
- **p06-all-vrf:** Combine p01, p02 and p03 to check resource interaction. PASS **41,924 / 148**, -615 cycles (-1.446%). This combination is better than its individual components because resource scheduling changes. Sent to root as the strongest completed first-batch candidate. The batch shell produced a trailing parser error after the final successful compile because its on-disk script had been modified to add flock while running; the individual compiler log is complete and the emitted schedule is valid. Selected candidates require the planned clean locked recompile regardless.

## Further mechanism probes

- **p07-quant-scale-vrf:** Produce dynamic quantization scale directly in VRF, clone the register handle for shard/projection mappings, remove two separate loads of the same scalar. Every physical slice already holds the all-reduced scalar before relabeling. Compiler rejects derived `VrfTensor::clone` in device MIR (`Backend::Storage` associated type unsupported). **p07b** consumes the scalar handle in successive reshapes after each borrow ends, avoiding clone; PASS **42,539 / 152**, same makespan with two fewer instructions. Not promoted without a measured benefit.
- **p08-switch-trf:** Send input all-gather directly from Switch to TRF, explicitly retaining the switch's non-canonical H wire order in NativeTrf. Compiler rejects `to_trf` because the stream includes `H % 8 # 32` padding while the proposed Element drops it. Reject; neither this path nor p05 silently relabels padding as valid activation data.
- **p09-parallel-v-exact:** Scale four per-slice V rows first and round them to BF16, then create full heads on Main while Sub forms partial mean squares and performs a 64-slice reduction. All BF16 boundaries retained; summation association changes. PASS **43,388 / 155**, +849 cycles; reject. The additional cross-slice reduction costs more than the exposed overlap saves.
- **p10-a010-parallel-v:** Fuse V head gather/scale on Main and duplicate gather/scale/mean-square on Sub, while preserving weighted input norm and both FP8 components. **Explicit numerical delta:** RMS statistics use FP32 scaled values before BF16 rounding; numerator retains BF16 scaling. For finite normal values the BF16 unit-roundoff bound `u=2^-8` bounds the corresponding norm ratio by `1±u` (ignoring reduction rounding); EPS reduces sensitivity. PASS **42,237 / 151**, weaker than exact fused p11's 41,712. Reject rather than add numerical risk without a performance advantage.
- **p11-fused-gather-scale:** Fuse head assembly and channel scaling for Q/K/V; retain the exact existing projection and scale BF16 boundaries. F32 conversion before Switch is exact for BF16 input. Removes full-head intermediate materialization and one Main pass per projection. Locked compile PASS **41,712 / 148**, -827 cycles (-1.944%). Source `e4fa8b13c83e4b77dd053356aaf3e78fd795b8063b8d7cc68b3ad87beabe6a38`.
- **p12-fused-gather-rms-vrf:** Combine p11 with p01. PASS **42,031 / 145**. Removing three more preloads shifts resource scheduling and is slower than p11's 41,712; instruction count alone is insufficient.
- **p13-rope-broadcast:** Starting from p06, request both indirect RoPE gathers with true broadcast distributions `Cluster=m![2]`, `Slice=m![256]`. The old layouts `m![1 # 2]` and `m![1 # 256]` pad one live unit, so their other positions cannot be relabeled as initialized heads. True broadcast distributions request a copy at every physical unit; only then may `reshape` label those copies as `HeadCluster`/`QueryHeads`. Locked compile PASS but **53,560 / 142**: replicating into all 512 slices is expensive. Reject this form. This deliberately does not reuse the invalid padded-gather shortcut.
- **p14-rope-head-broadcast:** Refine p13 to the exact live head positions: `Cluster=m![2]`, `Slice=m![8, 1 # 32]`. There are 8 initialized copies per cluster, at physical slices 0,32,...,224. Relabel them as `[Ns % 4, Gs, 1 # 32]`; K uses the already initialized Gs=0 positions 0,64,128,192. All other padded slots remain unused. Locked compile PASS **39,823 / 142**, -2,716 cycles (-6.385%). Each gather is 1,050 cycles instead of p13's 7,981. Source `b1d52a876bb8dd33758db72a6df696f81c5ea9ea2de842e3b2564549477f2e28`; root selected it for integrated public and generic-input tests.
- **p15-fused-rope-head-broadcast:** Combine p14 and exact head gather/scale fusion. PASS **39,698 / 136**, -2,841 cycles (-6.679%), 125 cycles and six instructions below p14. Only `qkv_head_local.rs` changes; `ops.rs` byte-identical. Source `fd035d3a19dab1a88f2278cbd2603beb4f84bf8dcc96a43858e11aefd5213b12`.
- **p16-rope-input-ring32:** On p14, replace input mean-square and calibration-max inferred inter-slice reductions by explicit ring32 gathers plus local FP32 reductions. Compiler rejects CustomBroadcast's snoop bitmap versus output enumeration (multi-ring layout). **p16b** uses `Broadcast1 { slice1: 32, slice0: 1 }`, retaining all 32 partials; PASS **39,823 / 142**, same makespan/count as p14. These input reductions are hidden under the large Q weight transfer. No static score gain.
- **p17-parallel-v-exact-ring64:** Replace p09's inferred V mean-square cross-slice reduction by an explicit 64-slice gather and local sum. Same BF16 row values and all 64 partials retained; requires matching p09 `ops.rs` body to avoid normalizing V twice. PASS **42,734 / 156**, 654 cycles better than p09 but 195 slower than baseline. Reject this V strategy.
- **p18-rope-kv-stripe:** One full-weight DMA fragmentation probe on p14: use A010's KV row stripe plus an actual Switch InterTranspose to restore canonical rows. Retain current dual-FP8 contraction, dynamic x scale, weighted input norm, BF16 rounding before channel scaling and every matrix byte. Only activation/scale operands are relabeled to the striped slice names: all physical slices already hold identical complete activation and calibration copies. Compiler rejects the VRF reference transmute because its backend Cluster labels remain Qs/2048 rather than Ns/4. **p18b** uses the actual SDK `VrfTensor::reshape` primitive, consuming the scale handle after Q projection. Its only ops body delta is passing `x_scale` by value to private `project_key_value`; external signatures and arithmetic remain unchanged. PASS **39,869 / 145**. K/V DMA each drops 7,030 to 6,966 cycles and total DMA occupancy drops 36,610 to 36,482, but added row rearrangement makes the complete schedule 46 cycles slower than p14 and 171 slower than p15. Reject current layout; the transfer improvement is real but its complete cost is unfavorable.

## Remaining resource floor

P14 and p15 each have **15 DMA instructions, 36,610 occupied DMA cycles**. The three full matrix loads remain **13,512 + 7,030 + 7,030 = 27,572 cycles**. P15's makespan is 3,088 cycles above its DMA occupancy; this is a compiler resource bound, not a runtime optimum proof.

Every FP8 matrix row is 3,840 bytes = 15 aligned 256-byte transactions. Current per-slice contiguous chunks are 30,720 bytes for Q (8 rows) and 15,360 bytes for K/V (4 rows), also 256-byte aligned. This makes a simple alignment fix unlikely; p18 specifically tests redistribution across the slice DMA network and pays the required output rearrangement cost.
